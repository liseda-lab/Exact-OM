# Controlled TRAIN packet admission

`tools.repair.train_packet_admission` authenticates the completed native worker,
all output digests and all 308 fixed slots before preparing two annotation shards.
It applies the frozen lossless text encoding uniformly to every complete native
packet, retaining raw packets, exact expansion proofs and original unavailable
outcomes. It never reacquires candidates or repeats native checks. Rows still
above the 32,768-byte or 8,000-token limit stay unavailable. The input estimate
reserves 64 extra tokens for the eventual request-run digest.

The hosted entry point validates the complete shard before its free account-key
check. Closed rows require the bound admission contract and never open a network
request; they remain in the report even if a different eligible row encounters a
provider failure. The unchanged strict annotation validator decides whether a
returned comparison is usable. An annotation process completing does not imply
usable weak supervision.

Admission retains the qualified MiniMax/Together profile, both request-amendment
lineages, every earlier reservation and the original acquisition/learning clocks.
The existing phase ledger conservatively charges 90 service seconds per attempted
request, including unknown deliveries, against the TRAIN/DEV/TEST service caps.
Frozen jobs use the existing source store, CPU/RAM reservations and dispatcher.
This admits TRAIN annotation only. Shared validated labels, required swap
aggregation, measured combined-loss/checkpoint/concurrent throughput, matched DEV
reserves and a common endpoint remain prerequisites for enabling the six fits.
The authored construction remains generator-dependent and generated-only; this
transport change supplies no independent expert or Conference evidence.
