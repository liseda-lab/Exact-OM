# Expanded corpus finalization

`tools.repair.expanded_corpus` binds the completed development profile to an
immutable structural split before regenerating evidence or paired cases. It
verifies the execution nonce, frozen profile source/runtime, every profile row,
selection and missing targets. The detached worker independently recomputes all
historical exposure and candidate fingerprints and the alias groups. Any source
or selection mismatch stops publication; no parent is replaced using outcomes.

The original 224-case training cohort (128 train, 32 development, 64 test) and
separate 64-case fresh-evaluation cohort remain the denominators. Profile parents
are excluded. Every selected parent has one corrupted and one coherent variant
under a new study/cohort identity, with unchanged structure and independently
regenerated evidence using the frozen seed and existing generator settings.
Native v3 observable inputs are separate from evaluator intentions. Each split
has a hashed release manifest and a loader-compatible preparation with no label
caches. Missing structures and failed materializations remain explicit rows.

The development profile records 60 complete compilations and four timeouts out
of 64 probes. That permits data materialization, not a claim about solve/label
viability, G0–G2, training, or learning efficiency. No scientific resource or
grammar setting changes here. The eight constructions use connected path,
branching and overlap variations; name-free grouping does not establish broad
semantic diversity or unseen-mechanism transfer.

A finite operational slice bounds the worker and each parent has a bounded
materialization call. Parent receipts and immutable exports support compatible
continuation with all prior costs retained. Materialization completion is only
the data stage: evaluation, training/labeling, robustness and scaling remain
registered and must validate its release receipt before consuming cases. Test
outcomes remain unopened; no teacher, native solver, model or API is queried.
